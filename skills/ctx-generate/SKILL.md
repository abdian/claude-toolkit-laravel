# Context generator

<!-- INSTALL: ~/.claude/skills/ctx-generate/SKILL.md -->

## Input
!`cat .claude/ctx/DECISIONS.md 2>/dev/null || echo "MISSING — run /ctx-interview first. Stop here."`

## Your job

Turn `DECISIONS.md` into working context files. Generate **only** from
decisions that are actually in that file. If a rule you want to write is not
backed by a decision, do not write it — report it as a gap instead.

Every generated file starts with this exact header:

```
<!-- GENERATED by /ctx-generate from .claude/ctx/DECISIONS.md — do not hand-edit. -->
<!-- Edit DECISIONS.md and re-run /ctx-generate. -->
```

Never overwrite a file lacking that header. If `CLAUDE.md` already exists and
was hand-written, show me a merge proposal and wait — do not clobber it.

## Budgets — HARD LIMITS, not guidelines

| Artifact | Limit |
|---|---|
| `CLAUDE.md` | 50 lines |
| Each `.claude/rules/*.md` | 30 lines |
| Number of rule files | 8 |
| Each `SKILL.md` body | 60 lines |

If you exceed a budget, do not raise it. Cut. A bloated context file causes
Claude to ignore the rules that matter, which is worse than having no file at
all. If something genuinely does not fit, that is a signal it belongs in a
skill (loaded on demand) rather than a rule (loaded always).

Apply this test to every single line you write:

> **"If I delete this line, will Claude make a mistake?"**

If no, delete it. Standard language conventions, "write clean code", anything
readable from the source itself, and anything Claude already does correctly
without being told — all cut.

## Routing: which decision goes where

| Decision type | Destination |
|---|---|
| Applies to every file in the repo | `CLAUDE.md` |
| Applies only to files matching a glob | `.claude/rules/<area>.md` with `paths:` |
| A repeatable multi-step procedure | `.claude/skills/<name>/SKILL.md` |
| Must happen every time with zero exceptions | propose a **hook**, do not write a rule |
| Occasional deep domain knowledge | `.claude/skills/` with a narrow `description` |

That fourth row matters: a rule is advisory and Claude can miss it under
context pressure. A hook is deterministic. If a decision says "always", "never
under any circumstances", or "must", propose the hook and say so — do not
silently downgrade it to a line of markdown.

## Writing rules

Every rule file:

```markdown
---
paths:
  - "src/components/**"
---
```

- Quote every glob. `"**/*.ts"` — unquoted breaks YAML silently.
- No `alwaysApply` — that field is from Cursor and does nothing here. For a
  global rule, omit `paths` entirely.
- Path-scoped rules load when Claude **reads** a matching file, which is not
  guaranteed when it **creates** one. Any rule that governs file creation
  ("every new component must…") goes in `CLAUDE.md` instead. Flag these
  explicitly when you route them.

**End every rule file with reference implementations:**

```markdown
## Reference implementations — read before writing
- Simple:        <path>
- With variants: <path>
Match these exactly.
```

This is the highest-leverage part of any rule. Three real paths beat twenty
lines of description, because the model learns the pattern from the example
rather than from your prose about the example.

## Writing skills

For each procedure in `DECISIONS.md`:
- `disable-model-invocation: true` if it has any side effect (deploy, commit,
  migrate, send). You do not want Claude deciding on its own that it is time.
- `description` must contain the phrases I would actually type, not a formal
  summary. This field is what triggers the skill; a beautiful description that
  matches nothing is a skill that never fires.
- Step 1 of any generation skill is always "read <reference file> and follow it".

## Output report

After writing, print:

1. Every file created or changed, with its line count vs its budget
2. **Unbacked rules** — anything you wanted to write but had no decision for.
   These go back to `/ctx-interview` as new questions, not into the files.
3. **Hook candidates** — decisions phrased as absolutes that deserve
   enforcement rather than advice
4. **Dropped** — decisions you deliberately left out to stay in budget, so I
   can promote them by hand if I disagree
5. This line:

> Next: run `/ctx-verify` — generated context that has not been tested is
> just text. Do not trust these files until they change behavior.
