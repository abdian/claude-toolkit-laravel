# پخش سند در specs — $ARGUMENTS

<!--
  RUN:  /spec-import سند-من.docx      (یا .md / .txt)
        /spec-import                  (بدون آرگومان: متنی که تو سشن پیست کردم)
  بعدش: /clear، و فقط برای شکاف‌های گزارش‌شده مصاحبه.
-->

## آماده‌سازی

- فایل: !`ls -l "$ARGUMENTS" 2>/dev/null || echo "آرگومانی نیامد — از متن پیست‌شده در سشن استفاده کن"`
- فایل‌های مقصد: !`ls specs/*.md`

اگر پسوند `.docx` است، اول تبدیلش کن. مبدل کنار همین skill نصب شده، پس این
یک خط هرجا که skill نصب شده باشد کار می‌کند:

```bash
CONV=""
for c in .claude/skills/spec-import/docx2md.py \
         "$HOME/.claude/skills/spec-import/docx2md.py" \
         _toolkit/docx2md.py claude-toolkit/docx2md.py; do
  [ -f "$c" ] && { CONV="$c"; break; }
done
python3 "$CONV" "$ARGUMENTS" > /tmp/brain-dump.md
```

اگر `CONV` خالی درآمد یعنی skill بدون فایل جانبی‌اش کپی شده — مستقیم
`docx2md.py` را از پوشه جعبه‌ابزار بردار.

بعد `/tmp/brain-dump.md` را کامل بخوان. اگر `.md` یا `.txt` است، مستقیم بخوان.

## قانون بنیادی — IMPORTANT

**فقط چیزی را بنویس که سند صریحاً گفته.** این کار مسیریابی است، نه نویسندگی.

هر جای خالی که سند جوابش را ندارد **خالی می‌ماند** و در گزارش شکاف‌ها می‌آید.
جای خالی را با یک جواب باورپذیر پر کردن، بدترین حالت ممکن است: کاربر هیچ‌وقت
متوجه نمی‌شود تصمیمی گرفته نشده، فقط پر شده — و شش ماه رویش کد می‌زند.

اگر برای یک ردیف جدول فقط نصف اطلاعات هست (مثلاً اسم فارسی هست ولی انگلیسی
نیست)، ردیف را با `[؟]` در ستون ناقص بنویس. نصفه‌ی صادق بهتر از کاملِ ساختگی است.

**هیچ‌وقت `[قلاب]`های تمپلیت را با حدس پر نکن.** یا سند جواب دارد، یا قلاب می‌ماند.

## نقشه مسیریابی

| چیزی که در سند می‌بینی | کجا می‌رود |
|---|---|
| محصول چیست، برای کیست، چه مشکلی حل می‌کند | `VISION.md` → «محصول در یک جمله» |
| کاربرها و مهم‌ترین کارشان | `VISION.md` → جدول کاربرها |
| کمترین نسخه‌ی قابل عرضه | `VISION.md` → MVP |
| «این را نمی‌سازیم» / «فعلاً نه» / «فاز دو» | `VISION.md` → Non-goals |
| اسم موجودیت‌ها (دوره، سفارش، کاربر، …) | `GLOSSARY.md` → جدول موجودیت‌ها |
| وضعیت‌ها (draft/published، pending/paid) | `GLOSSARY.md` → جدول enum ها |
| کی به چه چیزی دسترسی دارد | `PERMISSIONS.md` → سطر ماتریس |
| صفحات پنل‌ها، منوها | `PANELS.md` → یک ردیف هر صفحه |
| سرویس بیرونی (درگاه، پیامک، ورود) | `INTEGRATIONS.md` |
| مسیر چندمرحله‌ای که به سرویس بیرونی می‌خورد | `FLOWS.md` |
| تصمیم زیرساختی و دلیلش | `ARCHITECTURE.md` |
| فیچرها و ترتیب ساخت | `BACKLOG.md` → **فقط عنوان + یک خط** |

**جزئیات فیچر هیچ‌جا نمی‌رود.** سند احتمالاً پر از جزئیات صفحه و فرم است.
آن‌ها را در `BACKLOG.md` نچپان — عنوانش را بردار، بقیه‌اش را در گزارش زیر
عنوان «جزئیاتی که نگه نداشتم» فهرست کن تا روز ساخت با `/opsx:propose` بیاید.

## ترتیب کار

وابستگی دارد، پس این ترتیب اجباری است:

1. `VISION.md` — بقیه از اینجا معنی می‌گیرند
2. `GLOSSARY.md` — **قبل از هر فایل دیگری که اسم موجودیت دارد**
3. `PERMISSIONS.md`
4. `INTEGRATIONS.md`
5. `FLOWS.md` · `PANELS.md`
6. `BACKLOG.md`

از قدم ۳ به بعد، فقط از اسم‌هایی استفاده کن که در `GLOSSARY.md` نوشتی. اگر
سند برای یک چیز دو اسم مختلف به کار برده (سفارش/خرید)، **خودت یکی را انتخاب
نکن** — هر دو را در شکاف‌ها گزارش کن.

## گزارش پایانی — مهم‌ترین خروجی این skill

بعد از نوشتن فایل‌ها، این را چاپ کن. جدول اول، همان چیزی است که کاربر برای
ادامه لازم دارد:

```
## چی نوشته شد
| فایل | چند مورد | از کدام بخش سند |

## شکاف‌ها — این‌ها را سند جواب نداده
| فایل | چه چیزی کم است | چرا مهم است |

## تناقض‌ها
هر جا سند دو حرف متفاوت زده، یا با فایل‌های موجود نمی‌خواند.

## جزئیاتی که نگه نداشتم
جزئیات فیچر که عمداً در specs ننوشتم — روز ساخت با /opsx:propose می‌آیند.

## قدم بعد
یک خط: کدام فایل بیشترین شکاف را دارد و با کدام پرامپت پرش کند.
```

این شکاف‌ها را حتماً جداگانه چک کن، چون سندهای brain-dump تقریباً همیشه
ندارندشان و همان‌ها مهم‌ترین‌اند:

- **Non-goals** در `VISION.md` — آدم‌ها می‌نویسند چه می‌سازند، نه چه نمی‌سازند
- **اسم انگلیسی قطعی** هر موجودیت در `GLOSSARY.md`
- **مالک** هر موجودیت (کدام سرویس)
- سطرهای `[✓؟]` در `PERMISSIONS.md` که تصمیم کسب‌وکارند
- **«وقتی سرویس بالا نیست»** در `INTEGRATIONS.md` — تقریباً هیچ‌وقت در سند نیست
- **«اگه خراب شد»** هر فلو در `FLOWS.md` — سند فقط مسیر موفق را دارد
- **مجوز** هر صفحه در `PANELS.md`

## بعدش

در پاسخ نهایی بگو `/clear` کند و فقط برای شکاف‌ها مصاحبه‌ی کوتاه بزند — نه از
اول. سند کار قدم‌های آسان را کرده؛ چیزی که ماند، همان تصمیم‌های سختی است که
مصاحبه برای بیرون کشیدنشان ساخته شده.
